Why It Exists

The goal is not to claim false precision. The goal is to make the current model legible enough that users can judge whether a result is directionally useful, overconfident, or in need of a closer human review.

What this page is for

LEOFF Helper is meant to support retirement decisions, not replace judgment, professional tax advice, or legal planning. That means the dashboard should be transparent about what it assumes instead of pretending every result is exact.

This library documents the current live-beta assumptions that matter most when reading the dashboard: inflation, account growth, Social Security handling, pension math inputs, and the current Monte Carlo stress model.

Use this page as a trust layer

If the dashboard output surprises you, this is the first place to check whether the underlying assumptions match the way you actually expect retirement to work.

Inflation assumptions

The planner no longer treats inflation as one flat number everywhere. It now supports separate assumptions for goods and services, housing, and healthcare.

  • Goods and services inflation defaults to the general day-to-day spending path used in the current workspace.
  • Housing inflation is modeled separately so housing-heavy plans do not hide behind a generic blended rate.
  • Healthcare inflation is modeled separately because late-career and post-retirement medical costs tend to behave differently from baseline household inflation.

If a user leaves the inflation split at the suggested defaults, the dashboard is using the current built-in assumption set. If a user overrides those fields, the dashboard uses the user-entered rates instead.

Return and growth assumptions

Deterministic projections still need baseline growth assumptions. Those assumptions are not promises; they are planning anchors.

  • Retirement accounts and portfolios use the configured growth assumptions inside the current plan inputs.
  • Real-estate value growth and rent growth are modeled separately so a property can appreciate without assuming rent rises at the exact same rate.
  • Mortgage payoff timing now reflects configured extra-principal payments when those are present.

If you think the baseline return path is too optimistic or too conservative, the best fix is to change the underlying assumptions in the plan rather than simply reading more into a single dashboard output.

Social Security handling

Social Security is now handled with more input fidelity than the earliest versions of the planner. Users can model known monthly benefit values and claim timing rather than relying only on a rough generic estimate.

  • The planner can normalize known benefit inputs at age 62, full retirement age, or age 70 into the shared engine.
  • The premium Social Security optimizer compares age 62, FRA, and age 70 against the current plan rather than treating claiming as an isolated math problem.
  • The dashboard still treats Social Security claiming as a plan input, not a guaranteed recommendation independent of all other spending and withdrawal choices.

Pension, salary, and retirement-age handling

The dashboard now adjusts pension-sensitive assumptions when the retirement-age slider moves. That matters because waiting longer changes more than the start date.

  • Service credit is adjusted when the selected retirement age changes.
  • Final average salary assumptions are age-adjusted from current annual pay toward the selected retirement timing.
  • Portfolio withdrawal timing also shifts with the selected retirement age so the report does not compare mismatched timelines.

For LEOFF2, PERS2, and TRS2, the planner uses dedicated pension engines and formal pension functions rather than one-off UI math.

Monte Carlo boundaries

Monte Carlo is a stress test layered on top of the deterministic plan. It is not the same thing as a crystal ball.

  • It currently varies inflation, portfolio returns, and real-estate growth year by year around the current plan assumptions.
  • It does not automatically invent new spending behavior, new tax law, new survivor choices, or new pension rules.
  • Premium stress testing can push the run into harsher custom downside assumptions, but it is still bounded by the current modeling framework.
  • The dashboard uses stable seeding across retirement ages so slider comparisons stay more comparable instead of redrawing a completely unrelated random sample each time.
Monte Carlo is best used to judge durability, not certainty.

Known modeling limits and things not to over-read

There are still important things the current model does not fully capture. A few examples matter more than others:

  • Tax modeling is stronger than before, but still not a substitute for a year-by-year CPA review.
  • Monte Carlo uses independent year-by-year shocks today and does not yet model richer regime clustering or full recession-state persistence.
  • Estate guidance is planning support, not legal advice, and should not be treated as a trust or probate strategy.
  • The dashboard can inform retirement timing, but it should not be used as the only basis for irrevocable choices without pressure-testing the assumptions.

How to use this library responsibly

If a result looks too good, check the retirement age, expense inputs, portfolio growth assumptions, and bridge years first. If a result looks too bad, check the same things before assuming the planner is broken. In both cases, the key question is whether the plan assumptions are believable for the household making the decision.

If you want to adjust the plan, go back to the calculator. If you want to see the current report interpretation layer, open the dashboard. If you want the stress-model details, read How Monte Carlo Modeling Works in LEOFF Helper.
